# Review of §01.05 "The Stored-Program Machine"

Reviewer's scratch work: /tmp/r0105 (extracted listings, builds, simulator runs, gdb log).
Line numbers refer to `01.05.md`. Severity: **error** (definitely wrong, with evidence), **likely error**, **improvement**.

---

## Summary

- Every program in the section compiles cleanly, and every printed output that can be reproduced here matches **character for character**. That covers Listing 01.05-3, the n = 100, STORE 7, STORE 9, n = 3, multiply and relocation variants, Listing 01.05-5 (bytes and exit status 139), Listing 01.05-6 (layout), Listing 01.05-7 under simavr, the disassembly of Listing 01.05-8, the full avr-gdb session, and Listing 01.05-9 with the mock `Serial`. All "line N" references are correct. No code line is longer than 76 characters. The build files match the printed listings.
- The real problems are cross-references and a few technical over-statements:
  - Four forward references point to the wrong section. §06.04 is cited for index registers, §05.02 for character codes, and §03.06/§21.04 for relocation.
  - The :::metal box promises that §01.06 decodes `0c 94 34 00`, but §01.06 never does.
  - The same box presents the reset vector of the plain-C blink program as an Arduino sketch's vector "that calls your `setup()`".
  - The section claims "every `if`/`while`/`for` sets a flag". This contradicts §01.03, which says the Xtensa (one of the book's three machines) has no flags.
  - It says memory is "flip-flops". This contradicts §01.04 line 189.
  - It says "bytes that arrive as data can never be fetched as instructions" on the AVR. This contradicts the section's own account of the bootloader.
  - It says "every bit pattern decodes as something". This is false for x86-64.
  - It says "much of the ESP32's internal RAM" is dual-mapped. Only SRAM1 (128 KB of 520 KB) is.
- The front-matter `builds` line disagrees with toc.json.
- About 25 forward promises are not recorded in promises.md.

## What was checked and found correct

- **Programs and outputs.** Every C listing compiles without warnings under gcc-14 `-std=c23 -Wall -Wextra -pedantic` (selfcode.c also with `-O1 -fcf-protection=none`). Every AVR listing compiles under avr-gcc/avr-g++ 7.3.0. Every reproducible output matches character for character: tiny.c and all five variants, selfcode.c bytes and exit status 139, the maps.c layout, the selfread.c simavr line, the step.c disassembly, the full avr-gdb transcript, and selfread.ino under simavr with the mock. Address-dependent outputs are explained for 01.05-5 and in the Sources.
- **Arithmetic and counts.** Instruction counts 82, 802, 26 and 58. 5050 = 19 × 256 + 186. Encodings: `0x78` = ADD 24; `0x47` = STORE 7 and its decode `0x09` → HALT 9; `0x49`, `0x3B`, `0x5B`, `0xCC` and `0xA4` all correct. Cell 25 sequence for Experiment 01.05-1. `0x0F86` is the ADD r24,r22 encoding, stored low byte first. Word/byte addresses 0x5C/0xB8 and 0x48/0x90. The PC steps 0x48 → 0x49 → 0x4b (`sts` is 2 words).
- **Decodes.** `86 0F` on x86-64 is `xchg %cl,(%rdi)` ("something entirely unrelated" is right). `0c 94 34 00` = `jmp 0x68` (avr-objdump).
- **AVR facts.** Harvard architecture with separate memories and buses (datasheet wording, line 371). 14-bit PC, 16K × 16 flash, 131 instructions, mostly single-cycle. 32 × 8 registers. LPM/SPM and the boot-section restriction of SPM. `PROGMEM`/`F()` rely on LPM. No execution from SRAM. BOOTRST starting the bootloader. 512-byte bootloader at the top of flash (consistent with §01.04). Word addresses from avr-gcc function pointers.
- **x86-64 and Linux.** `lea`/`ret` bytes. 1–15-byte instructions; 16 GPRs. Split L1 caches of tens of KB. NX introduced in the early 2000s (AMD64 2003, Intel XD 2004). W^X. r-xp / rw-p / r--p permissions and 4096-byte pages. ASLR changes the high bits only. The `-fcf-protection` / `endbr64` remark. The shell exit status 128 + 11.
- **Xtensa.** 24-bit/16-bit (density) instructions; 64 ARs with a 16-register window on the ESP32 configuration; no flags (consistent with §01.03). IRAM 0x40080000–0x400A0000 and the 4-byte-aligned IRAM access rule (ESP-IDF *Memory Types*). IROM from 0x400D0000, DROM from 0x3F400000, DRAM from 0x3FFB0000 (0x3FFC0000 with Bluetooth) (ESP-IDF v4.1 *General Notes*).
- **History.**
  - Harvard Mark I (1944, tape, glued loops).
  - ENIAC (1945, plugboards).
  - *First Draft* (June 1945) and the credit dispute with Eckert and Mauchly.
  - Turing 1936 and ACE 1945–46.
  - Manchester Baby: first stored program on June 21, 1948, by Williams, Kilburn and Tootill. The IEEE milestone citation reads: "At this site on 21 June 1948 the 'Baby' became the first computer to execute a program stored in addressable read-write electronic memory… led to the 1949 Manchester Mark I which pioneered index registers."
  - Manchester Mark 1 index registers ("B-lines") in 1949.
  - EDSAC's first program, May 1949.
  - Backus's 1977 Turing Award lecture and "von Neumann bottleneck".
- **Voyager 1.**
  - The FDS is one of three onboard computers.
  - Readable data stopped on Nov. 14, 2023.
  - A single failed chip held part of the FDS memory, including software code.
  - The code was split and relocated because no single location could hold it.
  - The team had to "adjust those code sections to ensure … that they all still function as a whole".
  - The engineering patch was sent April 18 and the reply came April 20, 2024.
  - Light time is 22½ hours each way; the distance is 24 billion km.
  - The cause is unknown (wear or energetic particle; IEEE Spectrum).
  - All four instruments were back by June 2024.
  - Sources: JPL news, April 22, 2024; NASA Voyager blog, May 22, 2024; IEEE Spectrum.
- **Sibling consistency.** §01.06 relies on Listing 01.05-3, Table 01.05-1, Experiments 01.05-3/-4 (JZ 12 = `0xCC`, JUMP 4 = `0xA4`), Listing 01.05-8's `8D E0`/`ff cf`, and "the pipeline of §01.05". All of these are consistent with this section.
- **Build files.** tiny.c, t100.c, mul.c (same bytes), reloc_bad.c/reloc_ok.c, x86/selfcode.c, x86/maps.c, avr/selfread.c, avr/step.c, avr/step.gdb and uno/selfread.ino all match the printed listings. bundle/ is identical where compared.
- **TOC.** All five TOC bullets of 01.05 are covered.

## What could not be verified

- **Listing 01.05-10 (ESP32).** No ESP32 toolchain or board, so it was neither compiled nor run. The address ranges were checked against ESP-IDF documentation only. The ESP32 TRM PDF download was **blocked by the proxy (HTTP 403)**, so the SRAM0/1/2 bus mapping was checked against Espressif's "ESP32 Memory Map 101" article instead.
- **Listing 01.05-9 on a real Uno with the Arduino core.** Only the simavr + mock run was reproduced, as the author also states. The jump target in an Arduino sketch's reset vector was not reproduced (no Arduino core installed). See C2.
- **Fedora packaging of simavr and avr-gdb.** packages.fedoraproject.org could not be fetched; the text already flags this.
- **The "about 3%" corrupted FDS memory and the March 2024 "poke"** are taken from press coverage, as the Sources state; no NASA primary text was retrieved for them here.
- **The General Electric origin of all three Voyager computers.** Not confirmed; see C10.
- **Fedora's bash message wording** ("(core dumped)") is from general knowledge of systemd-coredump defaults and was not run on Fedora.
- **Printed font sizes** in the figures are estimated from image size, dpi and `{w=cm}`, not measured on paper.
